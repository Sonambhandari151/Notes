## Service Permissions

#### DLL : 
-  Dynamic Link Library
- Contains code, functions , or resources that programs can use.
- Similar to shared library (.so) in linux.

1. **Minimum Necessary Access**
    
    - Each service/account should have only the permissions it needs to function — nothing more.
        
2. **Avoid LocalSystem Unless Required**
    
    - LocalSystem = almost unlimited rights.
        
    - Most apps/services don’t need this → assign lower-privilege accounts instead.
        
3. **Use Dedicated Service Accounts**
    
    - Don’t run services under personal user accounts (like Bob).
        
    - Create unique accounts for each service.
        
4. **Separate Duties**
    
    - Different services → different accounts.
        
    - Limits the impact if one account/service is compromised.
        
5. **Control Directory/Executable Permissions**
    
    - Lock down NTFS permissions of service executables.
        
    - Prevent unauthorized modification of service binaries or DLLs.
        
6. **Review & Audit Regularly**
    
    - Periodically check what services run under which accounts.
        
    - Remove unnecessary privileges or disabled accounts tied to services.
        
7. **Reduce Attack Surface**
    
    - Lower-privilege accounts limit attacker ability to escalate if they hijack a service.

## 📝 Service Permissions 

### 1. Importance of Services

- Services = long-running processes critical to Windows OS.
    
- Often overlooked as **attack vectors** (can be abused to: load malicious DLLs, escalate privileges, maintain persistence).
    
- Misconfigurations happen due to **3rd-party software** installs or **admin mistakes**.
    

---

### 2. Service Accounts

- When installing services (e.g., **DHCP, AD DS**), they may run as the logged-in user.
    
- Risk: If that user leaves or account is disabled → service fails (e.g., DHCP can’t lease IPs).
    
- Best practice: Use **dedicated service accounts** for critical services.
    
- Built-in service accounts:
    
    - `LocalService`
        
    - `NetworkService`
        
    - `LocalSystem` (highest privileges).
        

---

### 3. Service Executable Path

- Each service has an **executable path** (binary it runs).
    
- Weak **NTFS permissions** on this directory → attacker can replace executable with malware.
    
- Misconfigured **binPath** can be redirected to malicious executables.
    

---

### 4. Principle of Least Privilege

- Most services run as **LocalSystem** (too powerful).
    
- Not all apps need that → better to assign minimal privileges.
    
- Research & configure services to run under least privilege possible.
    

---

### 5. Recovery Options

- Services have recovery actions if they fail (restart service, reboot computer, run a program).
    
- Attackers can abuse “run a program” to execute malicious files under service context.
    

---

### 6. Managing Services – Tools

- **GUI:** `services.msc` → user-friendly but not scriptable.
    
- **CLI (Command Prompt / PowerShell):**
    
    - `sc qc <ServiceName>` → query config.
        
    - `sc stop/start <ServiceName>` → manage service state.
        
    - `sc config <ServiceName> binPath= C:\Malware.exe` → modify binary path.
        
    - `sc sdshow <ServiceName>` → view permissions (SDDL).
        
    - **PowerShell:** `Get-ACL HKLM:\System\CurrentControlSet\Services\<ServiceName>` → readable format + SDDL.
        

---

### 7. Security Descriptors (SDDL)

- Every Windows service has a **Security Descriptor** (permissions).
    
- Two main lists:
    
    - **DACL** → who can access/modify.
        
    - **SACL** → what access attempts get audited.
        
- Example SDDL string:
    
    ```
    D:(A;;CCLCSWRPLORC;;;AU)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)
    ```
    
- Breakdown:
    
    - `D:` → DACL.
        
    - `(A;; … ;;;AU)` → Allow permissions to **Authenticated Users**.
        
    - Common rights:
        
        - `CC` → Query config
            
        - `LC` → Query status
            
        - `SW` → Enumerate dependents
            
        - `RP` → Start service
            
        - `LO` → Interrogate service
            
        - `RC` → Read control
            

---

### 8. Attack Surface

- Misconfigured service permissions let attackers:
    
    - Start/stop critical services.
        
    - Replace service executables.
        
    - Abuse recovery actions.
        
    - Escalate privileges (if service runs as **SYSTEM**).
        

---

✅ **Summary:**  
Services are a **double-edged sword** – essential for Windows but dangerous if misconfigured. Sysadmins must:

- Use **dedicated service accounts** (least privilege).
    
- Lock down **executable paths & directories**.
    
- Audit and understand **service permissions (SDDL)**.
    
- Monitor **recovery actions** to avoid abuse.

## Windows Sessions
### 🔹 Interactive Session

- Requires **user authentication** (username + password/domain credentials).
    
- Ways to initiate:
    
    - Local logon (physically on machine).
        
    - `runas` command (secondary session).
        
    - Remote Desktop (RDP).
        

### 🔹 Non-Interactive Session

- Do **not require login credentials**.
    
- Used by **Windows OS** to auto-start services and scheduled tasks.
    
- No password associated.
    
- Main types:
    

1. **Local System Account (NT AUTHORITY\SYSTEM)**
    
    - Most powerful account on Windows.
        
    - More powerful than local admin group.
        
    - Runs critical OS services.
        
2. **Local Service Account (NT AUTHORITY\LocalService)**
    
    - Limited privileges (like a local user).
        
    - Used to run some services safely.
        
3. **Network Service Account (NT AUTHORITY\NetworkService)**
    
    - Similar to Local Service but can authenticate over the network.
        
    - Can establish **authenticated sessions** with other systems/services.

## 📌 Windows Management Instrumentation (WMI) 

### 🔹 What is WMI?

- A **subsystem of Windows/PowerShell** used for system monitoring and management.
    
- Goal: **Centralize device & application management** across corporate networks.
    
- Built into Windows since **Windows 2000**.
    

---

### 🔹 WMI Components

1. **WMI Service** → Runs at boot, acts as intermediary between providers, repository, and apps.
    
2. **Managed Objects** → Logical/physical components managed by WMI.
    
3. **WMI Providers** → Gather data/events for specific objects.
    
4. **Classes** → Structures used by providers to pass data to WMI service.
    
5. **Methods** → Actions tied to classes (e.g., start/stop processes remotely).
    
6. **WMI Repository** → Database storing static WMI data.
    
7. **CIM Object Manager** → Handles requests from apps and retrieves data from providers.
    
8. **WMI API** → Enables applications to interact with WMI.
    
9. **WMI Consumer** → Executes queries through CIM Object Manager.
    

---

### 🔹 Uses of WMI

- Gather **status info** (local & remote systems).
    
- Configure **security settings** remotely.
    
- Manage **user/group permissions**.
    
- Modify **system properties**.
    
- **Execute code** remotely.
    
- Schedule processes.
    
- Setup **logging**.
    

---

### 🔹 WMIC (Command Line Interface for WMI)

- Run by typing `wmic` in CMD.
    
- **Deprecated** but still available in many systems.
    
- Uses **aliases + verbs/adverbs**.
    
- Examples:
    
    - `wmic computersystem get name` → Get hostname.
        
    - `wmic os list brief` → Get OS details.
        
    - `wmic bios get serialnumber` → Get system serial number.
        

**Common switches:**

- `/NODE` → Run against remote system(s).
    
- `/USER` `/PASSWORD` → Run under different credentials.
    
- `/OUTPUT` → Redirect results.
    
- `/NAMESPACE` → Define namespace.
    

---

### 🔹 PowerShell with WMI

- **Get-WmiObject** → Retrieve instances of WMI classes.
    
    ```powershell
    Get-WmiObject -Class Win32_OperatingSystem | 
    Select SystemDirectory,BuildNumber,SerialNumber,Version | ft
    ```
    
- **Invoke-WmiMethod** → Call class methods (e.g., rename file, start service).
    
    ```powershell
    Invoke-WmiMethod -Path "CIM_DataFile.Name='C:\users\public\spns.csv'" `
                     -Name Rename -ArgumentList "C:\Users\Public\kerberoasted_users.csv"
    ```
    
    - ReturnValue `0` → Success.
        

---

### 🔹 Key Differences:

- **WMIC** = Legacy CLI for WMI (simpler, but deprecated).
    
- **PowerShell WMI Cmdlets** = More powerful, modern, and script-friendly.

### Windows Subsystem for Linux (WSL)

1. **Definition**
    
    - WSL lets you run **Linux binaries natively** on Windows 10 and Windows Server 2019.
        
    - Made for developers to use Bash, Ruby, `sed`, `awk`, `grep`, etc. directly on Windows.
        
2. **WSL Versions**
    
    - **WSL1:** Translates Linux calls → Windows calls (no real Linux kernel).
        
    - **WSL2 (2019):** Uses a **real Linux kernel** with **Hyper-V features**, giving better performance and compatibility.
        
3. **Installation**
    
    - Run PowerShell (Admin):
        
        ```powershell
        Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux
        ```
        
    - Then install a Linux distro:
        
        - From Microsoft Store (Ubuntu, Debian, etc.).
            
        - Or manually download and unpack a distro.
            
4. **Bash Access**
    
    - WSL installs **Bash.exe** → just type `bash` in Windows console.
        
    - Gives a **Linux shell** with standard directory structure.
        
5. **Directory Structure**
    
    - Inside WSL: `/bin, /etc, /usr, /var, /mnt`, etc.
        
    - Windows drives are under `/mnt/` (e.g., `C:` → `/mnt/c`).
        
    - This allows **seamless file access** between Windows & Linux.
        
6. **Usage**
    
    - From the Bash shell, you can:
        
        - Run Linux commands.
            
        - Install packages.
            
        - Update system.
            
    - Example:
        
        ```bash
        uname -a
        ```
        
        Shows Linux kernel details running on Windows.

- **Desktop Experience** = full GUI, easy to use, but heavier.

- If performance, security, and minimal footprint matter → use **Server Core**.
    
- If ease of management and GUI tools are needed → use **Desktop Experience**.

### 🔐 Windows Security Basics

- Windows has many features, apps, and settings → if misconfigured, hackers can exploit them.
    
- Even patched systems can still be attacked if security isn’t set properly.
    
- Microsoft keeps adding new features to make Windows safer.

### 👤 Security Identifier (SID)

- Every **user, computer, or process** in Windows gets a unique ID called **SID**.
    
- Even if two users have the same name, their **SID is different**, so Windows can tell them apart.
    
- SID looks like a long string: `S-1-5-21-674899381-4069889467-2080702030-1002`.
    

**SID parts:**

- **S** → Just means “this is a SID”.
    
- **1** → Revision level (always 1).
    
- **5** → Authority that created the SID (Windows itself).
    
- **21** → Subauthority, tells relation/order.
    
- **674899381-4069889467-2080702030** → Which computer or domain created it.
    
- **1002** → RID (Relative ID), says what type of account: normal user, admin, guest, etc.
    

So basically, **SID = user’s fingerprint in Windows security**.

---

### 📘 SAM (Security Accounts Manager)

- Think of **SAM** like a database in Windows.
    
- It **stores usernames, passwords, and their rights**.
    
- Example: “Bob can log in” or “Alice is an Admin”.
    

---

### 📜 Access Control Lists (ACLs) and Entries (ACEs)

- ACL = A list that controls **who can access what**.
    
- ACE = One rule in that list.
    
    - Example: “Bob can read this file” is one ACE.
        
    - “Alice can read and write” is another ACE.
        

There are two types of ACLs:

1. **DACL (Discretionary ACL):** Who is allowed or denied access.
    
2. **SACL (System ACL):** Who is monitored/audited when accessing something.
    

---

### 🎟️ Access Tokens

- When you log in, Windows gives you an **access token**.
    
- This token contains:
    
    - Your **SID** (who you are).
        
    - Your groups (admin, users, etc.).
        
    - Your privileges (what you can do).
        
- Every time you try to open a file or run something, Windows checks your token against ACLs to decide **Allow or Deny**.
    

---

✅ In short:

- **SID = Unique ID of user**
    
- **SAM = Database of users/passwords**
    
- **ACL/ACE = Who can do what**
    
- **Access token = Your ID card for actions**

### 🔑 Registry Value Types 

1. **REG_BINARY**
    
    - Stores data in **raw binary (0s and 1s)** format.
        
    - Example: hardware settings, encryption keys.
        
2. **REG_DWORD** (32-bit number)
    
    - Stores a **number up to 4 bytes (32-bit)**.
        
    - Example: `1 = enabled`, `0 = disabled`.
        
3. **REG_DWORD_LITTLE_ENDIAN**
    
    - Same as **REG_DWORD** (Windows uses little-endian by default).
        
    - Just means numbers are stored in a certain byte order.
        
4. **REG_DWORD_BIG_ENDIAN**
    
    - Same 32-bit number but stored in **big-endian format**.
        
    - Rare in Windows (more common in UNIX).
        
5. **REG_EXPAND_SZ**
    
    - A **string that can contain environment variables** like `%PATH%`.
        
    - Example: `C:\Users\%USERNAME%\Documents` → expands to your actual username folder.
        
6. **REG_LINK**
    
    - A **shortcut (symbolic link)** to another registry key.
        
    - Used when one key points to another.
        
7. **REG_MULTI_SZ**
    
    - A **list of strings** separated by `\0`.
        
    - Example: multiple file paths or service names.
        
8. **REG_NONE**
    
    - No specific type (rarely used).
        
9. **REG_QWORD** (64-bit number)
    
    - Stores a **number up to 8 bytes (64-bit)**.
        
    - Example: used for large counters or memory addresses.
        
10. **REG_QWORD_LITTLE_ENDIAN**
    

- Same as **REG_QWORD**, stored in little-endian format (default in Windows).
    

11. **REG_SZ**
    

- A **normal text string**.
    
- Example: `"C:\Program Files\AppName"`
    

---

👉 In short:

- **Numbers → DWORD (32-bit) or QWORD (64-bit)**
    
- **Text → SZ (normal) or EXPAND_SZ (with variables)**
    
- **Lists → MULTI_SZ**
    
- **Binary → BINARY**
